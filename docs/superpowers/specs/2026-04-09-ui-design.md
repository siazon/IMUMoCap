# UI Design Spec — IMUMoCap Gait Feedback System
Date: 2026-04-09

## Overview

Two UI surfaces:
1. **WPF desktop app** — operator monitoring + configuration on the PC running Xsens SDK
2. **AR HUD (XREAL Unity app)** — real-time footprint feedback on AR glasses, WebSocket-only receive

---

## Part 1: WPF Desktop App

### Layout

Left-right split:

| Left panel (flex) | Right panel (fixed ~260px) |
|---|---|
| Status grid + log | Parameters + buttons |

#### Left Panel

**Top: Status Grid** (always visible)

| Column | Content |
|---|---|
| Device | Pelvis / Left / Right |
| Status | OK / RSSI Low / Error |
| Packets | Running count |
| Cal State | WaitingForStart / CollectingStaticPose / Completed / Failed |
| PD (°) | Current progression direction in degrees |
| FPA L (°) | Latest left FPA |
| FPA R (°) | Latest right FPA |

**Bottom: Log Panel** (collapsible, default visible)
- `TextBox` with `IsReadOnly=True`, `VerticalScrollBarVisibility=Auto`, auto-scrolls to bottom
- Receives events from `GaitPipeline.OnLog`
- Toggle button: "隐藏日志 / 显示日志"

#### Right Panel

**Tunable Parameters** (collapsible, default visible — label above each slider/input)

| # | Parameter | Type | Default | Range |
|---|---|---|---|---|
| 1 | Stomp threshold (m/s²) | Slider | 25 | 10–50 |
| 2 | Static gyro threshold (rad/s) | Slider | 0.3 | 0.05–1.0 |
| 3 | Stance free-acc threshold (m/s²) | Slider | 2.5 | 0.5–5.0 |
| 4 | Stance gyro threshold (rad/s) | Slider | 1.0 | 0.1–3.0 |
| 5 | PD confidence threshold | Slider | 0.7 | 0.3–1.0 |
| 6 | PD stability threshold | Slider | 0.7 | 0.3–1.0 |
| 7 | Min baseline steps | Slider (int) | 20 | 10–50 |

Parameters are applied live (no restart needed). Pipeline exposes a `PipelineParams` record; UI binds to it.

**Buttons** (below parameters)

- `重新开始校准` — calls `_pipeline.Reset()` then restarts calibration; enabled only when connected
- `保存诊断数据 (CSV)` — exports accumulated `DiagnosticsRow` list to a timestamped CSV file

**Toggle buttons (above parameters)**
- `隐藏参数 / 显示参数` — collapses the parameters section

---

### DiagnosticsRow CSV Format

One row per valid frame. Columns:

```
Timestamp, PacketId,
Pelvis_AccX, Pelvis_AccY, Pelvis_AccZ, Pelvis_GyrX, Pelvis_GyrY, Pelvis_GyrZ, Pelvis_QuatW, Pelvis_QuatX, Pelvis_QuatY, Pelvis_QuatZ,
Left_AccX, Left_AccY, Left_AccZ, Left_GyrX, Left_GyrY, Left_GyrZ, Left_QuatW, Left_QuatX, Left_QuatY, Left_QuatZ,
Right_AccX, Right_AccY, Right_AccZ, Right_GyrX, Right_GyrY, Right_GyrZ, Right_QuatW, Right_QuatX, Right_QuatY, Right_QuatZ,
GaitEvent_LeftStance, GaitEvent_RightStance, GaitEvent_IsWalking,
MotionContext_State, MotionContext_Confidence,
PD_DirectionDeg, PD_Stability, PD_IsValid,
FPA_Left_Deg, FPA_Left_Error, FPA_Left_OnTarget,
FPA_Right_Deg, FPA_Right_Error, FPA_Right_OnTarget
```

Buffer stored in `List<DiagnosticsRow>` in `GaitPipeline`. Cleared on `Reset()`.

## Part 2: XREAL AR HUD (Unity App)

### Architecture

- Platform: XREAL glasses, Unity 2022 LTS, XREAL NRSDK
- Communication: WebSocket client (`NativeWebSocket` package), receive-only
- Canvas: Camera-space (follows head), 2D HUD overlay

### WebSocket Messages Received

**`type:"fpa"`** (existing)
```json
{ "type": "fpa", "left": -3.2, "right": 4.1, "targetLeft": 0, "targetRight": 0, "toleranceLeft": 3, "toleranceRight": 3 }
```

**`type:"state"`** (new — to add on PC side)
```json
{ "type": "state", "state": "waiting" | "calibrating" | "baseline" | "training" | "error" }
```

### Five Display States

| State | Display |
|---|---|
| `waiting` | Text: "请用左脚跺地开始校准" |
| `calibrating` | Text: "校准中，请保持静止站立" |
| `baseline` | Text: "Baseline 采集中，请自然行走" |
| `training` | Hide text; show footprint icons |
| `error` | Text: "校准失败，请等待重新开始" |

### Footprint Display (training state only)

- Show **latest step only** (one left + one right footprint icon)
- **Green** = `OnTarget == true`
- **Red** = `OnTarget == false`
- Icons: simple flat footprint sprites (L / R silhouettes)
- Position: centered bottom-third of HUD canvas
- Footprints update on each new `type:"fpa"` message

### Canvas Layout (Camera-space)

```
┌─────────────────────────────────┐
│                                 │
│       [state text center]       │
│                                 │
│   [Left foot]   [Right foot]    │  ← bottom third, training state only
└─────────────────────────────────┘
```

### WebSocket Connection

- WS server: `ws://192.168.x.x:8080` (IP configured in Unity Inspector)
- Auto-reconnect on disconnect (3s retry)
- No messages sent from AR glasses to PC

## PC-Side Changes Required

### Add `type:"state"` broadcast

In `GaitPipeline.cs` (or `MainWindow.xaml.cs`):
- Broadcast `{"type":"state","state":"..."}` on every `OnCalibrationStateChanged` event
- Map `CalibrationState` → string state:
  - `WaitingForStart` → `"waiting"`
  - `CollectingStaticPose` → `"calibrating"`
  - `Completed` + baseline active → `"baseline"`
  - `Completed` + training active → `"training"`
  - `Failed` → `"error"`

### Add DiagnosticsRow collection in GaitPipeline

- `List<DiagnosticsRow> _diagnosticsBuffer` field
- Append to buffer in `Process()` after all pipeline stages run
- `public List<DiagnosticsRow> GetDiagnosticsSnapshot()` — returns copy for CSV export

### Add PipelineParams live update

- `public PipelineParams Params { get; set; }` on `GaitPipeline`
- Each sub-processor reads from `Params` on every call (no caching in constructor)

---

## Out of Scope

- AR glasses sending control commands back to PC
- Historical footprint trails (only latest step shown)
- Cloud sync or remote monitoring
- Baseline editing after collection
